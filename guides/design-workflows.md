# 디자인 작업 · 무엇부터 연결할까요?

[Agent Stack Brief](../README.md) · **한국어** · [English](design-workflows.en.md) · [카탈로그](../catalog/README.md)

디자인 판단, 디자인 원본 읽기, 컴포넌트 검색은 다른 작업입니다. **원하는 결과 하나**로 고르세요. 셋 모두 설치할 필요는 없습니다.

## 1. 기존 화면이 밋밋하거나 쓰기 어려워요

**자료:** [Impeccable](https://github.com/pbakaus/impeccable). 기존 항목의 활용 경로를 보강했습니다.

에이전트용 디자인 검토·정리·마무리 지침과 도구입니다. Figma 연결 서버가 아닙니다. 설치·초기화는 원본을 따르고, 훅은 실행 내용과 신뢰 승인을 별도로 검토하세요. 버전마다 명령 형식이 다를 수 있습니다.

**첫 요청**

> 대상 독자와 핵심 행동을 확인하고 정보 위계·간격·타이포그래피 문제 세 개를 우선순위로 정리해 주세요. 브랜드와 기능은 유지하고 합의한 한 화면만 개선한 뒤 모바일·키보드 검증 근거를 남겨 주세요.

**완료 기준:** 문제 → 변경 → 검증 근거. ‘예뻐졌다’만으로 완료하지 않습니다.

<a id="figma"></a>

## 2. Figma 디자인을 기존 코드로 옮기고 싶어요

**자료:** [Figma MCP 공식 안내](https://developers.figma.com/docs/figma-mcp-server/).

디자인 문맥을 에이전트에 연결합니다. 원격·데스크톱 서버의 기능·접근 조건이 다르므로 [환경별 연결 안내](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/)를 확인하세요. 계정·파일 권한이 필요하며, 캔버스 쓰기가 가능한 구성도 있어 읽기와 변경을 구분합니다.

**첫 요청**

> 허용한 Figma 프레임 하나를 읽고 기존 컴포넌트·토큰과 대응표를 먼저 만들어 주세요. 없는 상태·에셋은 미확인으로 남겨 주세요. 원본 파일은 변경하지 말고 승인한 코드 범위에서 구현한 뒤 차이를 보고해 주세요.

**완료 기준:** 프레임 출처, 재사용한 토큰·컴포넌트, 상태별 구현과 차이 목록. 보기 권한으로 쓰기 권한을 가정하지 않습니다.

<a id="components"></a>

## 3. 필요한 UI 컴포넌트를 찾아 구현하고 싶어요

**자료:** [shadcn MCP 공식 안내](https://ui.shadcn.com/docs/mcp).

레지스트리 컴포넌트를 탐색·검색·설치합니다. 디자인 판단을 대신하지 않습니다. 지원 스택·레지스트리 설정과 설치 diff를 검토하고 비공개 인증 정보는 공유하지 마세요.

**첫 요청**

> 호환되는 폼 컴포넌트 두 개를 검색하고 의존성·파일 변경을 먼저 보여 주세요. 승인 전 설치하지 마세요. 선택 후 기존 토큰에 맞추고 빈 상태·오류·키보드 포커스를 검증해 주세요.

**완료 기준:** 선택 이유, 설치 diff, 정상·오류·키보드 결과. 컴포넌트 추가만으로 접근성 검증이 끝나지는 않습니다.

## 공통으로 남길 것

대상 화면과 독자 → 유지할 브랜드·기능 → 변경 범위 → 정상·빈 상태·오류 → 작은 화면·키보드 결과를 기록하세요. 효과를 늘리기 전에 핵심 행동이 더 명확해졌는지 확인합니다.
