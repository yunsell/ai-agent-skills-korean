## 01 / Skills — 검사 누락도 결과입니다

**발표:** 2026-10-15 한국 시간 · **대상:** Skill Scanner·스킬 배포 CI 사용자 · **판단:** 업데이트와 CI 규칙 검토

**사실:** Skill Scanner 2.3.0은 따라가지 않은 심볼릭 링크를 `SYMLINK_NOT_SCANNED`, `scan-all`에서 로드하지 못한 스킬을 `SKILL_LOAD_FAILED`로 보고합니다. 분류 코드와 YAML frontmatter 검사도 바뀌었습니다. [원본 릴리스](https://github.com/cisco-ai-defense/skill-scanner/releases/tag/2.3.0)

**의미 — 편집 의견:** 탐지 건수만 줄었다고 더 안전해진 것은 아닙니다. 검사 범위가 줄어도 같은 결과처럼 보일 수 있습니다.

**다음 행동:** 고정된 스킬 묶음으로 변경 전후 결과를 비교하고, 미검사·로드 실패 항목을 따로 검토하세요. 새 탐지 항목과 분류 코드 변경이 기존 SARIF(분석 결과 교환 형식) 필터·`--fail-on-severity` 종료 코드에 미치는 영향도 확인하세요.

**시작 위치:** [2.3.0 설치·사용법](https://github.com/cisco-ai-defense/skill-scanner/blob/2.3.0/README.md). 현재 검사 중인 스킬 묶음을 고정해 버전 변경 전후에 사용하세요.

**확인할 결과:** 미검사 링크·로드 실패가 있는 묶음에서 해당 탐지 항목, SARIF 보고서, CI 종료 코드를 함께 확인합니다.

## 02 / MCP — ‘동작합니다’에 진단 근거를 붙이세요

**발표:** 2026-10-15 한국 시간 · **대상:** Chrome DevTools MCP로 웹을 검증하는 개발자 · **판단:** 진단 흐름에 시험 도입

**사실:** Chrome DevTools MCP 1.11.0은 FFmpeg 없이 동작하는 screencast 도구를 기본 활성화하고, `performance_start_trace`에 `ignoreCache`를 추가했습니다. `lighthouse_audit`는 실패한 감사 항목과 DOM 노드를 결과에 직접 포함합니다. [원본 릴리스](https://github.com/ChromeDevTools/chrome-devtools-mcp/releases/tag/chrome-devtools-mcp-v1.11.0)

**의미 — 편집 의견:** 화면을 통과했다는 설명보다 재현 영상과 진단 결과가 리뷰에 유용합니다. 캐시 조건이 다르면 성능 비교도 달라집니다.

**다음 행동:** 시험 브라우저에서 화면 하나를 골라 재현 단계·녹화·감사 결과를 함께 남기세요. 전후 비교에는 캐시 조건을 명시하세요.

**시작 위치:** [설정과 복사할 요청이 있는 실습](../guides/web-validation.md). 기대 결과가 정해진 네 단계로 시작합니다.

**확인할 결과:** 검색 결과 3 → 2 → 0 → 3과 화면 근거를 기록합니다. 녹화·성능 진단은 그다음 단계로 시도할 수 있습니다.

## 03 / Harness — 멈춘 것과 기다리는 것을 구분하세요

**발표:** 0.7.26은 2026-10-16, 0.7.27·0.7.28은 2026-10-17 한국 시간 · **대상:** Deep Agents 비동기 서브에이전트·ContextHubBackend 사용자 · **판단:** 관측·경로 회귀 테스트

**사실:** Deep Agents 0.7.26은 비동기 서브에이전트의 사람 대기 상태와 부모 작업 아래의 실행 기록(trace)을, 0.7.27은 메인 에이전트로의 상태 업데이트를 추가했습니다. 0.7.28은 `ContextHubBackend.glob`이 `path`를 따르도록 수정합니다. [0.7.26](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.26) · [0.7.27](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.27) · [0.7.28](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.28)

**의미 — 편집 의견:** 승인 대기를 시간 초과로 처리하면 같은 작업을 중복 실행할 수 있습니다. 진행 표시뿐 아니라 운영 판단에도 상태 구분이 필요합니다.

**다음 행동:** 사용하는 SDK 버전을 고정하고, 승인 대기·완료·실패를 구분해 기록하는 시험을 만드세요. 해당 백엔드를 쓴다면 하위 경로의 glob 결과도 회귀 검사하세요. 상태 알림과 경로 수정이 권한 강제를 대신하는 것은 아닙니다.

**시작 위치:** [공식 비동기 서브에이전트 안내](https://docs.langchain.com/oss/python/deepagents/async-subagents). 사용하는 SDK 버전과 예제의 지원 범위를 대조하세요.

**확인할 결과:** 승인 대기·완료·실패가 구분된 기록과, 지정한 하위 경로에 맞는 glob 결과를 남깁니다.
