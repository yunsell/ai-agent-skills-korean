> 창간호 편집 노트 — 새 도구보다 먼저 점검할 것은 실행 경계입니다. 오늘 나온 수정과 최근의 중요한 수정을 함께 골랐습니다. 발표일은 아래에 따로 표시하며, 모든 소식이 오늘 발표된 것은 아닙니다.

## 이번 호, 세 줄 요약

- **MCP·CLI:** 응답 유실과 실행 실패는 다릅니다. 재시도 전에 결과를 확인하세요.
- **Harness:** 승인한 문자열 경로뿐 아니라 실제 파일 대상의 권한도 확인하세요.
- **Skills:** 보안 검사 도구도 업데이트하고, 검사 결과를 사람의 검토와 함께 사용하세요.

<a id="browser"></a>

## 01 / MCP·CLI — 재시도에도 경계가 필요합니다

**발표:** 2026-10-14 한국 시간 · **대상:** agent-browser CLI/MCP 사용자 · **판단:** 업데이트 검토

**사실:** agent-browser 0.39.1은 데몬 응답 유실 뒤 변경·실행 명령이 중복 실행될 수 있던 재시도를 수정했습니다. 요청 전송 뒤 결과를 모르면 CLI JSON/MCP 응답에 `outcome_unknown`을 알립니다. [원본 릴리스](https://github.com/vercel-labs/agent-browser/releases/tag/v0.39.1)

**의미 — 편집 의견:** 응답이 없다는 이유만으로 쓰기 작업을 반복하면 안 됩니다.

**다음 행동:** 갱신을 검토하고, 불명확한 결과를 만나면 현재 상태를 확인한 뒤 재시도하세요. 읽기와 쓰기의 재시도 규칙을 나누는 것이 좋습니다.

<a id="harness"></a>

## 02 / Harness — 경로 이름이 아니라 실제 대상을 확인하세요

**발표:** 2026-10-14 한국 시간 · **대상:** Deep Agents 파일 백엔드·승인 규칙 사용자 · **판단:** 업데이트 검토

**사실:** Deep Agents 0.7.25는 요청 경로와 심볼릭 링크가 가리키는 실제 경로를 모두 권한·승인 검사에 반영합니다. 이전에는 검사 후 링크를 따라가 차단된 경로에 접근할 가능성이 있었습니다. [원본 릴리스](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.25)

**의미 — 편집 의견:** 좋은 프롬프트가 파일 접근 경계를 대신하지는 못합니다.

**다음 행동:** 해당 구성을 사용한다면 수정 버전을 검토하고, 링크 대상까지 권한 규칙이 적용되는지 격리 환경에서 확인하세요.

<a id="skills"></a>

## 03 / Skills — 검사 도구도 점검 대상입니다

**발표:** 2.2.1은 2026-10-06, 2.2.2는 2026-10-09 한국 시간 · **대상:** Skill Scanner 사용자 · **판단:** 업데이트 검토

**사실:** Skill Scanner 2.2.1은 비신뢰 TAR·Markdown 처리를 수정했고, 2.2.2는 정적 탐지와 의존성 수정을 추가했습니다. [2.2.1](https://github.com/cisco-ai-defense/skill-scanner/releases/tag/2.2.1) · [2.2.2](https://github.com/cisco-ai-defense/skill-scanner/releases/tag/2.2.2)

**의미 — 편집 의견:** 스캐너 자체의 버전도 도입 검토의 일부입니다.

**다음 행동:** 2.2.0 사용자라면 수정 릴리스를 검토하세요. 스캔 통과를 안전 보장으로 해석하지 마세요.

## 하나만 살펴본다면 / Deep Agents

**용도:** 파일·컨텍스트·도구·승인 흐름을 묶는 하네스를 검토할 때. **새로 출시된 도구라는 뜻은 아닙니다.**

[원본 README](https://github.com/langchain-ai/deepagents)는 파일시스템, 서브에이전트, 컨텍스트 관리와 스킬을 함께 제공한다고 설명합니다. 실행 구성을 조합하는 수고를 줄일 수 있지만, 도구 권한과 샌드박스는 별도로 설계해야 합니다. 채택 권고나 성능 순위가 아닌 **문서 기반 검토 후보**입니다.

[카탈로그의 Harnesses](../catalog/README.md#harnesses)에서 이어 읽으세요.

<a id="experiment"></a>

## 이번 호의 작은 실험 / 읽기 전용 조사 흐름

조합: **프로젝트 스킬 + GitHub MCP의 읽기 도구 + 사용 중인 하네스의 승인 규칙**.

1. 공개 저장소 또는 격리된 시험 프로젝트를 선택하고, 쓰기·배포 도구는 연결하지 않습니다.
2. 이슈 하나를 읽고 관련 파일과 수정 계획만 정리하도록 요청합니다.
3. 에이전트의 설명이 아니라 실제 노출 도구·권한 설정을 확인합니다. 지원되는 환경에서 거부 동작을 별도로 시험하세요.

**첫 요청 예시**

> 이슈와 관련 파일을 읽고 근거 링크, 원인 가설, 수정 계획을 정리해 주세요. 파일 변경·댓글 작성·배포는 하지 마세요. 결과가 불명확하면 쓰기 작업을 재시도하지 말고 현재 상태부터 보고해 주세요.

**완료 기준:** 읽은 근거, 노출된 도구와 권한 설정, 승인 경계, 실행·거부 기록(시험한 경우). 이 예시 자체는 검증 결과가 아닙니다. [GitHub MCP 설정 원본](https://github.com/github/github-mcp-server#read-only-mode)
